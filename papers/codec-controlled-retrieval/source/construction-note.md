# Codec-controlled retrieval: a theorem-grade note

This note is the theorem-grade companion to `docs/CODESPACE_NONMEMBERS.md`.
Where that document reports the empirical "codec controls the non-member
output distribution" finding and gives a numerical sanity check, this note
states and proves the underlying claims rigorously. It is destined to
become the mathematical substance of the towell2026codec paper. The
results are organized as a sequence of theorems T1 through T5; this file
establishes T1 and T2 (the idealized uniformity result on the stored-pattern
span), T3 (frequency independence), T4 (the sharp codec-control threshold,
stated as transversality of W to the codec's class partition), and T5 (the
real-incidence deviation, characterizing how far the real near-uniform ribbon
band departs from the T1 idealization). The security model (the FreqDist game
and its formal statement) is the dedicated section "Security: frequency-analysis
resistance (the FreqDist game)" after T5.

Throughout, all arithmetic on patterns is over the field GF(2): vector
addition is bitwise XOR and scalar multiplication is bitwise AND. An
M-bit pattern is an element of the vector space GF(2)^M. We write a^T z
for the GF(2) matrix-vector product (an XOR of selected rows of z), v in W
for set membership, A subset B for set inclusion, A intersect B for
intersection, and |A| for cardinality.

## T1 and T2: non-member output is uniform on the stored-pattern span

### Setup and facts about the real code

We fix a single solvable instance of `ribbon_retrieval<M>` built over a
key set S with a value codec `prefix_codec<V, M>`. The following facts are
read directly from `include/maph/retrieval/ribbon_retrieval.hpp` and
`include/maph/retrieval/encoded_retrieval.hpp`.

- The retrieval holds a solution vector `solution_` of `num_rows` entries,
  each an M-bit `value_type`. Write `num_rows = m` and stack the entries
  as the rows of an m-by-M matrix z over GF(2); row i is `solution_[i]`.

- For a key y, `lookup(y)` computes `row_spec_for(y) = (start, coeffs)`,
  where `coeffs` is a 64-bit odd word (the low bit is forced to 1) and
  `start` is a band offset in [0, m - W + 1) with band width W = 64. Then
  `query_row(start, coeffs)` returns the XOR of `solution_[start + bit]`
  over every set bit `bit` of `coeffs`. Define the band-indicator vector
  a_y in {0,1}^m to be the 64 bits of `coeffs` placed at offset `start`
  (bit `start + j` of a_y equals bit j of `coeffs`), and 0 elsewhere. Then

      lookup(y) = a_y^T z.

  This is the key structural fact: lookup is a GF(2)-linear function of
  the fixed solution matrix z, with the per-key coefficient vector a_y.
  It is NOT a 3-wise XOR. The vector a_y is a dense band: it has up to 64
  set bits, on the order of half of them on average (a pseudorandom odd
  64-bit word has about 32 set bits), all confined to a single 64-slot
  window [start, start + 64). We will use this density in T1; for now we
  only need linearity.

- For x in S, the builder solved the banded GF(2) linear system so that
  a_x^T z = c(x), where c(x) is the stored canonical codeword pattern of
  x's value v(x). Concretely the codec composition stores
  `codec_.encode(v(x))`, the left-aligned canonical codeword of v(x), as
  the right-hand side for x's row; "solvable instance" means the builder's
  forward elimination plus back-substitution produced a z reproducing
  every such equation (the final verification loop in `build()` confirms
  a_x^T z = c(x) for all x in S before returning).

Define the stored-pattern span

    W = span_{GF(2)} { c(x) : x in S },

the GF(2) subspace of GF(2)^M generated by the stored canonical codeword
patterns. We also use the row space of z,

    R(z) = { a^T z : a in {0,1}^m } = span_{GF(2)} { rows of z },

which is exactly the set of all GF(2) combinations of the rows of z.

The claim of T2 is that the set of values a non-member query can return,
after decoding, is governed by W; specifically R(z) = W and the reachable
outputs lie in and span W. The claim of T1 is that under an idealized
model (M1), which posits a_y^T z ~ Uniform(W) directly on that support, the
pre-decoding output is uniform on W. Together they give the formula

    P(out(y) = v) = |class(v) intersect W| / |W|,

where class(v) = { p in GF(2)^M : decode(p) = v } is the codec's decode
class of v. We prove this in five steps.

### Step 1: every query output lies in the row space R(z)

For any key y, lookup(y) = a_y^T z. By definition a_y^T z is the XOR of
the rows of z selected by the set bits of a_y, hence a GF(2) linear
combination of the rows of z. Therefore

    lookup(y) in R(z)    for every key y, member or not.

This holds with no assumption on y; it is pure linearity of the query map.

### Step 2: W is contained in R(z)

Each generator of W is a member output: for x in S, c(x) = a_x^T z is a
row-space element by Step 1. A subspace generated by elements of R(z) is
contained in R(z) (R(z) is closed under XOR). Hence

    W subset R(z).

### Step 3: the row space satisfies R(z) = W, and reachable outputs span W

We now show that every row of z lies in W, hence R(z) subset W; combined
with Step 2 (W subset R(z)) this gives the row-space identity R(z) = W.
For the reachable outputs specifically we prove only what is true: they are
contained in W and they span W (each stored generator c(x) is reachable by
its own member key x). We do NOT claim the reachable set equals W as a raw
set: a non-generator element of W need not be the output a_y^T z of any
single band-indicator a_y. The argument is a direct reading of how the
builder fills z.

Read the back-substitution block of `build()`:

    out.solution_.assign(out.num_rows_, 0);          // (i)  all slots 0
    for (size_t col = out.num_rows_; col-- > 0;) {
        if (pivot_coeffs[col] == 0) continue;        // (ii) skip free slots
        value_type val = pivot_value[col];           // (iii) RHS for this pivot
        ... val ^= out.solution_[ref] ...            // (iv) XOR solved downstream
        out.solution_[col] = val;                    // (v)  assign pivot slot
    }

Two structural properties follow.

(P1) Free slots are zero. A column `col` is a pivot column iff
`pivot_coeffs[col] != 0` after forward elimination. Line (i)
value-initializes every entry of z to the zero pattern, and only pivot
columns are ever assigned (line (v) runs only when (ii) does not skip).
Therefore `solution_[col] = 0` for every non-pivot ("free") column. The
zero pattern is in W trivially (0 = empty XOR of generators).

(P2) Every pivot slot is a GF(2) combination of the stored patterns
{ c(x) }, hence lies in W. During forward elimination the right-hand side
carried for each pivot, `pivot_value[col]`, is built only from the stored
values v of the incoming rows by the update `v = v ^ pivot_value[col]`,
starting from v = r.value = c(x) for the row of some x in S. By the same
closed-under-XOR induction used below, each `pivot_value[col]` accumulates
XORs of the c(x) and of other (earlier) `pivot_value` entries, which are
themselves XORs of the c(x); so every `pivot_value[col]` is an XOR of some
subset of { c(x) }, an element of W. Back-substitution then sets
`solution_[col]` to `pivot_value[col]` XORed with already-assigned
downstream entries `solution_[ref]`. By induction on decreasing `col` (the
loop runs from the largest column down, and each referenced
`ref = col + offset + bit > col` was assigned in an earlier iteration),
each `solution_[col]` is an XOR of elements of W, hence itself in W (W is
closed under XOR). Out-of-range references (`ref >= num_rows`) are dropped
by the builder and contribute 0, which is in W, so they preserve the
in-W property.

By (P1) and (P2) every row of z is an element of W:

    rows of z subset W.

A query output a_y^T z is an XOR of rows of z, so it is an XOR of elements
of W, hence in W. This holds for every key y. Therefore the reachable
output set is contained in W:

    { a_y^T z : y any key } subset W.

Moreover the reachable outputs span W: every generator c(x) of W is itself
a reachable output a_x^T z (the member key x realizes its own stored
pattern), so W = span{ c(x) } subset span{ a_y^T z : y any key }. The
reachable set therefore spans W without necessarily equalling it as a raw
set: a non-generator w in W (an XOR of two or more c(x)) need not be the
output of any single band-indicator a_y.

For the full row space the identity is exact: by (P1)/(P2) the rows of z
lie in W so R(z) subset W, and by Step 2 W subset R(z). Hence

    R(z) = W.

This is the proven T2 invariant. Here R(z) = { a^T z : a in {0,1}^m } ranges
over ALL coefficient vectors, not only the realizable band-indicators a_y;
that full quantification is what makes the equality hold.

Genericity condition (stated explicitly). Step 3 relies on exactly two
facts about the solved instance: (a) free slots are zero, and (b) every
occupied (pivot) slot is a GF(2) combination of the stored right-hand
sides. Both are guaranteed by the builder as written: (a) by the
value-initialization on line (i) plus the pivot-only assignment, and (b)
by the elimination carrying right-hand sides that are XORs of the c(x).
There is no step in the builder that injects a pattern outside W into z
(no random fill of free slots, no fingerprint salt added to a value).
Should a future builder variant fill free slots with nonzero patterns, or
add a non-W constant to the right-hand sides, this step would fail and the
reachable set could exceed W; the property is therefore a property of this
builder, not of ribbon retrieval in the abstract. The computational check
in `tests/v3/test_prefix_codec.cpp` (tag `[span]`) verifies the inclusion
direction consistent with this corrected statement: across 30000 distinct
non-member queries every output's re-encoded canonical pattern landed in W
(basis computed from the three stored canonical patterns), with zero
violations. This confirms reachable outputs subset W (and so R(z) = W,
since W subset R(z) always); it does not, and need not, assert raw-set
equality of the reachable set with W. Part (b) of the same test separately
verifies the frequency formula derived below.

### Step 4 (T1): the idealized uniform-on-W model

T1 is an explicit IDEALIZATION. We do not derive uniformity from the
structure of the real band a_y; we posit it directly on the image W, study
its consequence, and defer the exact gap between the real construction and
this idealization to T5.

The idealized model M1. For a non-member query y, model the pre-decoding
output as if a_y^T z were drawn uniformly at random from W:

    M1:    a_y^T z ~ Uniform(W),    i.e.    P(a_y^T z = w) = 1 / |W|
                                            for every w in W.

This is the limiting, best-case behavior, the maximally-mixing target the
real construction approaches. It is taken here as a hypothesis, NOT proven
from the band geometry.

Why M1 is the right idealization to study. The support is correct and is
proven: by Step 3 the row space is R(z) = W, the reachable outputs are
contained in W, and they span W, so W is exactly the set of patterns a
query output can range over and every element of W is in principle in play
(each generator is realized by a member key). What M1 adds on top of this
proven support is a symmetry assumption, flatness across W. A band a_y that
mixed the rows of z maximally, hitting every fiber of the query map equally,
would realize Uniform(W) exactly; M1 is the idealization in which the band
is that maximally-mixing object. It is the natural reference distribution:
the most-mixed law the construction could induce on its proven support W.

Remark (why we do not route this through uniform-on-A). One might hope to
derive M1 from a more primitive assumption, that a_y is uniform on its
band support

    A = { a in {0,1}^m : a is a length-64 band of an odd word at a legal
                         offset },

via the following standard fact.

  Lemma (image of a uniform vector under a linear map). Let L : GF(2)^m ->
  GF(2)^M be GF(2)-linear, L(a) = a^T z. Suppose U is uniform on a set
  A subset GF(2)^m and, for every w in L(A), the fiber
  |{ a in A : L(a) = w }| has the same size. Then L(U) is uniform on L(A).
  Proof: each w in L(A) has exactly |A| / |L(A)| preimages in A, so
  P(L(U) = w) = (|A| / |L(A)|) / |A| = 1 / |L(A)|, independent of w. The
  cleanest sufficient condition for the equal-fiber hypothesis is that A be
  a subspace surjecting onto W, in which case every nonempty fiber is a
  coset of ker(L) intersect A and the fibers partition A into equal parts.

This route does NOT apply to the real band support. A is not a subspace of
GF(2)^m: it excludes the zero vector, it pins the low bit of the band word
to 1 (odd `coeffs`), and it confines all set bits to a single 64-slot
window. The equal-fiber hypothesis is therefore unproven for A and is
generically false, and surjectivity L(A) = W alone is not sufficient for
uniformity of L(U). Because the hypothesis we actually want lives on the
image, we adopt uniformity on W (M1) as a direct hypothesis rather than
attempting to manufacture it from uniform-on-A. (For the linear map itself,
note im L = R(z) = W taken over the FULL domain GF(2)^m, the proven Step-3
identity; this is a statement about all coefficient vectors, and we do not
conflate it with the stronger, unneeded, and false claim that the band
support alone surjects with equal fibers.)

Consequence. Under M1, by definition,

    a_y^T z is uniform on W,    i.e.    P(a_y^T z = w) = 1 / |W| for all w in W.

Division of labor (T1 versus T5). T1 is exactly the conditional statement
"given the uniform-on-W action of M1, the codec-controlled formula of
Step 5 holds." It says nothing about how close the real construction comes
to M1. The real a_y is NOT uniform on W: it is the deterministic image of
`membership_fingerprint(y)` through the fixed mixing in `row_spec_for`, the
64-bit `coeffs` word is odd rather than fully free, and a single band cannot
select two rows more than 63 apart, so the real band induces only a
near-uniform law on W. Quantifying that residual, showing the real ribbon
band induces a distribution within a stated bound of Uniform(W), is the
separate subject of T5. T1 supplies the idealized target; T5 measures the
deviation from it.

### Step 5: decoding yields the codec-controlled formula

The codec composition decodes the pre-decoding output:
out(y) = decode(lookup(y)) = decode(a_y^T z). For a target logical value v
with decode class class(v) = { p in GF(2)^M : decode(p) = v },

    P(out(y) = v) = P(a_y^T z in class(v)).

Under M1, a_y^T z is uniform on W, so the probability of landing in any
subset of GF(2)^M equals the fraction of W in that subset:

    P(out(y) = v) = P(a_y^T z in class(v) intersect W)
                  = |class(v) intersect W| / |W|.

(The intersection with W is automatic because a_y^T z in W always, by
Step 3 (reachable outputs subset W); values v whose entire class misses W
receive probability 0, regardless of how the codec weights them. This is
the geometric threshold of `docs/CODESPACE_NONMEMBERS.md`.) This is
precisely the span-restricted prediction the `[span]` test verifies: part
(b) of that test
enumerates W, decodes each element, tallies per value, normalizes by |W|,
and checks the observed non-member frequencies match to within 0.03. For
the balanced length-2 codec with stored canonical patterns A = 0000,
B = 0100, C = 1000, the span of { A, B, C } is { 0000, 0100, 1000, 1100 }
of size 4, with one element decoding to each of A, B, C, D, so each
predicted share is 1/4, matching the observed non-member frequencies.

### Summary of T1 and T2

- T2 (support): the row space of the solved matrix z satisfies R(z) = W,
  the GF(2) span of the stored canonical patterns, under the builder's
  genericity condition (free slots zero, occupied slots are XORs of stored
  patterns). The reachable non-member outputs are contained in W and span
  W; they are not claimed to equal W as a raw set (a non-generator element
  of W need not be the output of any single band-indicator).
- T1 (uniformity): this is an idealization, model M1, which posits the
  pre-decoding output a_y^T z ~ Uniform(W) directly on the proven support
  W. It is not derived from the band structure. Under M1 the pre-decoding
  output is uniform on W, and decoding gives
  P(out(y) = v) = |class(v) intersect W| / |W|.
- The real ribbon band is only near-uniform on W; the deviation of the real
  construction from M1 is characterized separately as T5.

## T3: frequency independence

T3 isolates exactly what the non-member output law depends on. The
storage of a key/value map fixes two separate things: the value SUPPORT,
the set of distinct values that occur, and the MULTIPLICITIES, how many
keys carry each value. T3 says the non-member output distribution is a
function of the support and the codec only; the multiplicities never enter
it. This is the security lemma the later frequency-analysis result
(FreqDist) rests on.

### Setup

Let the codec be fixed. A key/value assignment over a key set S induces,
for each value v in the support, a stored canonical pattern c(x) = codec
.encode(v(x)) that depends only on v(x), not on x. Two distinct keys
mapped to the same value store the same canonical pattern. Define the
multiplicities

    m_v = |{ x in S : value(x) = v }|,    v in support,

and the underlying SET of distinct stored patterns

    supp = { c(x) : x in S } = { codec.encode(v) : v in support }.

The set supp is determined by the value support alone: it has one element
per distinct value, the canonical pattern of that value, regardless of how
many keys realize that value. The multiset of stored right-hand sides
(c(x) repeated m_{v(x)} times across the rows) does depend on the m_v, but
its underlying set supp does not.

### The argument

By definition (from the T1/T2 setup),

    W = span_{GF(2)} { c(x) : x in S } = span_{GF(2)}(supp).

The span of a multiset of vectors equals the span of its underlying set:
adjoining a vector that is already present (a repeated generator) adds
nothing to the set of GF(2) combinations, since any combination using a
repeated generator twice cancels (g XOR g = 0) and using it once is
already available from the single copy. Formally, span(multiset) =
span(set of distinct elements) because a linear span depends only on which
vectors are available as summands, not on how many times each is listed.
Therefore

    W = span_{GF(2)}(supp),

a function of supp only. Since supp is fixed by the value support and is
independent of the multiplicities m_v, we conclude

    W is invariant under any change of the m_v that preserves the support.

By T2, the solved row space satisfies R(z) = W, and by T1 (under the
idealization M1) the non-member output law is

    P(out(y) = v) = |class(v) intersect W| / |W|,

which is a function of W and the codec's decode classes only. Both inputs
to this formula, W and the classes class(v), are independent of the m_v.
Hence the idealized non-member output distribution is independent of the
storage frequencies.

### The T3 lemma

LEMMA (T3, frequency independence). Fix a codec. Let two key/value
assignments have the same value support but arbitrary, possibly very
different, multiplicities m_v and m'_v. Then they induce the same stored-
pattern span W, and therefore the same idealized non-member output
distribution P(out = v) = |class(v) intersect W| / |W|. In the real
construction the two distributions are not exactly equal: each build solves
a different banded system and so has its own solution matrix z, giving its
own near-uniform (rather than exactly uniform) law on the shared W. The two
real distributions therefore differ only by the per-build T5 deviation from
Uniform(W), a quantity bounded by the T5 analysis and independent of the
storage frequencies. No frequency-dependent term appears in either the
idealized law or the T5 error budget.

### Consequence for security (FreqDist)

T3 is the lemma the frequency-analysis security result depends on. An
adversary who probes the structure with non-member keys and observes their
outputs is sampling from the law P(out = v) = |class(v) intersect W| / |W|
(up to the T5 deviation). Because the storage frequencies m_v never enter
this law, no amount of non-member probing reveals them: two databases with
identical support but opposite frequency profiles (for example one almost
entirely a single value, the other balanced) present statistically
indistinguishable non-member output distributions. The non-member channel
leaks the support and the codec, which are public design choices, and
nothing about how often each value is actually stored. This is what lets
FreqDist argue that classical frequency analysis, which attacks the
correlation between output frequency and plaintext frequency, has no
purchase on the non-member outputs of this construction. The FreqDist game
itself, and the theorem that the idealized advantage is exactly zero, are
formalized in the security section below ("Security: frequency-analysis
resistance (the FreqDist game)"), which takes this lemma as its main input.

### Computational confirmation

The contrastive test in `tests/v3/test_prefix_codec.cpp` (tag
`[contrastive]`) is the empirical check of T3. It builds two
`encoded_retrieval<ribbon_retrieval<4>, prefix_codec<V, 4>>` structures
with the SAME codec (prefix lengths A:1, B:2, C:2) and the SAME value
support {A, B, C}, but storage frequencies 99% / 0.5% / 0.5% for the first
and 50% / 25% / 25% for the second, a raw frequency gap of up to 0.49 per
value. The test confirms both predictions of T3 directly:

1. Shared W. It computes the basis of W once from the shared support,
   stored = { encode(A), encode(B), encode(C) }, and checks that the
   re-encoded canonical pattern of every non-member output of BOTH
   structures lies in this single W (`gf2_in_span`), with zero violations
   across the probed non-member keys. This is the T2 support identity
   instantiated on the common W that T3 guarantees the two builds share.

2. Frequency independence. It measures each structure's non-member output
   frequencies over 30000 distinct keys and requires that the two
   distributions agree per category to within 4*se, where
   se = sqrt(2 p (1 - p) / N) with p ~ 0.25 and N = 30000 (4*se ~ 0.0141).
   Observed gaps |fa - fb| are about 0.0035 (A), 0.0044 (B), 0.0009 (C),
   comfortably inside the bound and far below the 0.49 raw frequency gap
   that would appear if storage frequency leaked. The residual is the
   per-build T5 deviation (the two builds have different solution matrices
   z), not a frequency-dependent term: it does not track the 99/0.5/0.5 vs
   50/25/25 difference. Both distributions also sit within 0.03 of the
   codec's class shares 0.50 / 0.25 / 0.25, as T1 predicts. The contrastive
   test is thus the joint empirical confirmation of T1, T2, and T3 on a
   shared support: same codec, same W, frequency-invariant output.

## T4: the sharp codec-control threshold

T1 gives the idealized non-member law P(out = v) = |class(v) intersect W| / |W|. T3 shows
that law depends only on the value support (through W) and the codec. T4 answers the next
question precisely: for which supports does that law equal the codec's own codespace shares,
P(out = v) = alpha(v) for EVERY v ("full codec control"), and what happens at the boundary. The
answer is a single sharp threshold stated as a transversality condition between W and the codec's
class partition, with NO intermediate regime: control is all (every class at its share) or
graded-but-degenerate (a strict subset of classes, each over-weighted by the same factor, the rest
exactly zero).

### Setup: a balanced linear codec and its class partition

We work with a BALANCED linear codec: all K = 2^(log2 K) values have codewords of equal length
log2 K, so each class has the same size and alpha(v) = 1/K for every v. For prefix_codec this is the
case of equal codeword lengths (e.g. the length-2 codec on M = 4, K = 4). "Linear" here is a
property of the class partition, made precise as follows.

Let C be the homophone subspace, the set of M-bit patterns whose top log2 K codeword bits are zero:

    C = { p in GF(2)^M : the top log2 K bits of p are 0 }.

C is a GF(2) subspace of dimension M - log2 K, with |C| = 2^(M - log2 K). The key structural fact
about a balanced linear codec is that its classes are exactly the cosets of C: two patterns decode
to the same value iff they share the same top log2 K codeword bits, iff they differ by an element of
C. So each class is a coset t + C of size |C|, and

    alpha(v) = |class(v)| / 2^M = |C| / 2^M = 2^(-log2 K) = 1/K.

Form the value quotient

    Q = GF(2)^M / C,

a GF(2) vector space of dimension log2 K, whose K points are precisely the K classes (the cosets of
C). Let

    pi : GF(2)^M -> Q

be the quotient map (concretely, projection onto the top log2 K codeword bits, discarding the low
M - log2 K within-class bits). Then pi(p) names the class of p, and pi is GF(2)-linear and surjective
with kernel C.

For prefix_codec specifically the canonical patterns are LEFT-ALIGNED: encode(v) places v's codeword
in the top log2 K bits and zeros the low M - log2 K bits. So the canonical patterns lie in a
transversal of C (the "low bits zero" transversal), and pi is INJECTIVE on the set of canonical
patterns: distinct values have distinct codewords, hence distinct images under pi. We use this at the
end to identify rank pi|_W with gf2_rank of the stored canonical patterns.

### Key lemma (subspace meets coset)

LEMMA. Let W be a GF(2) subspace of GF(2)^M and let t + C be any coset of the subspace C. Then the
intersection W intersect (t + C) is either empty or a coset of the subspace W intersect C; in
particular its size is either 0 or |W intersect C|, a constant independent of t.

PROOF. If W intersect (t + C) is empty there is nothing to prove. Otherwise pick
w0 in W intersect (t + C). We claim W intersect (t + C) = w0 + (W intersect C). For the forward
inclusion, take any w in W intersect (t + C). Both w and w0 lie in W, so w XOR w0 lies in W (W is a
subspace). Both lie in t + C, so w XOR w0 lies in (t + C) XOR (t + C) = C (the coset difference of a
coset of C is C: (t + c1) XOR (t + c2) = c1 XOR c2 in C). Hence w XOR w0 lies in W intersect C, so
w = w0 XOR (w XOR w0) lies in w0 + (W intersect C). For the reverse inclusion, any
w0 XOR u with u in W intersect C lies in W (both terms in W) and in t + C (w0 in t + C and u in C, so
w0 XOR u in t + C). Thus the intersection is the coset w0 + (W intersect C), of size
|W intersect C|. QED.

The lemma is the crux: it says a subspace meets every class it touches in the SAME number of points,
so the per-class mass is a two-valued quantity (a fixed positive constant on hit classes, zero on
missed classes). There is no room for a class to be partially filled at some intermediate density.

### The mass on each class is 0 or 1/K'

Apply the lemma with the classes class(v) = t_v + C. The per-class mass under T1 is

    q(v) = |class(v) intersect W| / |W|,

which by the lemma is 0 if W misses class(v), and |W intersect C| / |W| (the same value for every hit
class) otherwise. A class v is hit iff some w in W has pi(w) = pi(t_v), i.e. iff the class (as a point
of Q) lies in the image pi(W). So the number of hit classes is

    K' := |pi(W)| = 2^(rank pi|_W),

the size of the image of W under pi (a subspace of Q, hence a power of two).

To evaluate the constant hit-class mass, restrict pi to W. The restriction pi|_W : W -> Q is a
GF(2)-linear map with image pi(W) and kernel { w in W : pi(w) = 0 } = W intersect C. The first
isomorphism theorem (equivalently rank-nullity over GF(2), or a direct coset count) gives the
counting identity

    |W| = |pi(W)| * |W intersect C| = K' * |W intersect C|.

Therefore the constant hit-class mass is

    |W intersect C| / |W| = 1 / |pi(W)| = 1 / K'.

So the entire idealized law is the step function

    q(v) = 1/K'   if class v is hit (pi(t_v) in pi(W)),
    q(v) = 0      if class v is missed,

with exactly K' classes hit. These K' values sum to K' * (1/K') = 1, as a probability law must.

### Full control iff transversality (rank pi|_W = log2 K), and sharpness

Full codec control means q(v) = alpha(v) = 1/K for EVERY value v. From the step function this
requires two things at once: every class is hit (no zero entry), and the common hit-class mass equals
1/K, i.e. 1/K' = 1/K, i.e. K' = K. Both hold iff pi(W) = Q, the whole quotient, equivalently

    rank pi|_W = log2 K.

This is the TRANSVERSALITY condition: W is transversal to the class partition exactly when its image
under the class-naming projection pi is all of Q (W meets every coset of C). Equivalently, the
projection of W onto the value quotient Q = GF(2)^M / C is surjective.

SHARPNESS. The transition is a step in K' = 2^(rank pi|_W) and is therefore a step in the entire mass
vector q. As soon as pi(W) is a PROPER subspace of Q (K' < K, i.e. rank pi|_W < log2 K) there is no
partial credit and no graded approach to alpha:

  - the K' hit classes are each OVER-weighted to 1/K' which is STRICTLY GREATER than alpha = 1/K (by
    the exact factor K/K' > 1, since K' < K), and
  - the K - K' missed classes are EXACTLY zero, not small.

Raising K' to the next attainable value (the next power of two) is the only way the vector can change;
it jumps discontinuously. There is no intermediate regime in which some class sits strictly between 0
and 1/K, nor one in which the hit classes drift gradually toward alpha. The mass vector is a step
function of the single integer rank pi|_W, flipping to the flat 1/K profile precisely at
rank pi|_W = log2 K.

### Connection to the canonical-pattern picture and the engineering rule

For prefix_codec the canonical patterns are left-aligned (low M - log2 K bits zero), so the stored
canonical patterns lie in the "low bits zero" transversal of C, on which pi is injective. Two stored
canonical patterns are equal modulo C iff they are equal as patterns (their low bits already agree, at
zero), so a GF(2) dependence among the stored patterns holds iff the corresponding dependence holds
among their pi-images.

The step from "pi injective on stored patterns" to "rank pi|_W = gf2_rank(stored patterns)" requires
pi to be injective on ALL of W, not just on the generating set. This follows from the transversal
containment: the canonical patterns lie in the transversal T = { p in GF(2)^M : the low M - log2 K
bits of p are zero }, which is itself a subspace of GF(2)^M with T intersect C = {0} (an element
of T has its low M - log2 K bits zero; an element of C has its top log2 K bits zero; the only
pattern satisfying both conditions is 0). Since the stored patterns lie in T and T is a subspace,
W = span(stored patterns) is contained in T, and therefore W intersect C subset T intersect C = {0},
so W intersect C = {0}. With W intersect C = {0} the kernel of pi|_W is trivial, meaning pi is
injective on all of W, so |pi(W)| = |W| and rank pi|_W = dim W = gf2_rank(stored canonical patterns).

Hence

    rank pi|_W = rank of { pi(stored patterns) } = gf2_rank(stored canonical patterns),

the ordinary GF(2) rank of the stored patterns computed by gf2_rank. The transversality threshold
rank pi|_W = log2 K becomes the concrete, checkable condition

    gf2_rank(stored canonical patterns) = log2 K.

This is exactly the engineering rule of docs/CODESPACE_NONMEMBERS.md: store at least log2 K linearly
independent canonical patterns (equivalently, enough distinct values that the stored codewords span
the full log2 K codeword bits). Below that rank, control is lost in the sharp way above; at or above
it (rank saturates at log2 K, since pi(W) is a subspace of the log2 K-dimensional Q), control is full.

WORKED INSTANCE (the Step-1 check). For the balanced length-2 codec on M = 4, K = 4, the canonical
patterns are A = 0b0000, B = 0b0100, C = 0b1000, D = 0b1100 (confirmed by reading prefix_codec's
canonical assignment: codewords 0, 1, 2, 3 left-aligned into 4 bits), each class of size 4,
alpha = 1/4. Here log2 K = 2 and C = { 0000, 0001, 0010, 0011 } (top two bits zero), |C| = 4.

  - Store values {A, B}: stored patterns {0000, 0100}, gf2_rank = 1 < log2 K = 2. The span is
    W = {0000, 0100}, K' = |pi(W)| = 2 hit classes. Predicted mass [A, B, C, D] = [1/2, 1/2, 0, 0]:
    the two hit classes A, B are over-weighted to 1/K' = 1/2 (twice alpha), and C, D are exactly zero.
  - Store values {A, B, C}: stored patterns {0000, 0100, 1000}, gf2_rank = 2 = log2 K. Now D = 1100 =
    0100 XOR 1000 lies in W even though it was never stored, so W = {0000, 0100, 1000, 1100} = a full
    transversal-completion: pi(W) = Q, K' = 4. Predicted mass [1/4, 1/4, 1/4, 1/4] = alpha for all
    four values. This is full control, and it confirms that what matters is membership of a class in
    pi(W), not whether that class's value was stored.

These are the two vectors the `[threshold]` check asserts EXACTLY (tolerance 1e-9, since the masses are
dyadic rationals over the enumerated |W|): rank 1 gives [1/2, 1/2, 0, 0] and rank 2 gives
[1/4, 1/4, 1/4, 1/4], with gf2_rank pinned at 1 and 2 respectively, tying the flip to the rank
crossing log2 K. Note: the hit-class mass is in general 1/K' = |W intersect C| / |W|, not
1 / |W|. It coincides with 1 / |W| in these instances ONLY because the stored canonical patterns
are left-aligned, giving W intersect C = {0} (as shown above), so |W intersect C| = 1 and
K' = |W| / 1 = |W|. For an arbitrary W (not contained in the "low bits zero" transversal T),
the correct per-hit-class mass is |W intersect C| / |W| = 1 / K', which need not equal 1 / |W|. The same M = 4 patterns are the worked example in docs/CODESPACE_NONMEMBERS.md and the
[span] test's balanced length-2 codec.

### Remark: the general (skewed / variable-length) codec

The clean coset-counting argument above uses one feature of the balanced case essentially: a SINGLE
homophone subspace C describes the whole partition, so every class is a coset of the same subspace and
the subspace-meets-coset lemma applies uniformly. For a SKEWED codec (variable codeword lengths, as in
a genuine Huffman code) the classes have UNEQUAL sizes 2^(M - l_v) and are cosets of DIFFERENT
subspaces (the within-class directions of value v are the low M - l_v bits, a subspace C_v whose
dimension depends on l_v). There is no common C, so the lemma does not apply uniformly and the mass
need not be two-valued: different classes can carry different positive densities. Concretely, the
single-subspace lemma's two-valued conclusion (mass is 0 or the same constant 1/K' on every hit
class) no longer applies, because that conclusion depends on ALL classes being cosets of the SAME C.
Whether a genuinely graded regime (distinct positive masses on distinct hit classes) is achievable
for some specific skewed codec and some W is not established here and we do not claim it.

The full-control condition still has a clean abstract statement: control holds iff for every value v,

    |class(v) intersect W| / |W| = alpha(v),

i.e. W meets each class in proportion to that class's size. This is a "W is in general position with
respect to the (unequal) class partition" condition. But characterizing WHICH supports W achieve it,
and describing the failure modes (is the skewed transition still sharp, or genuinely graded?), is not
settled by the balanced argument and we do NOT claim it here. We state the balanced threshold as the
proven, sharp result and explicitly DEFER a full characterization of the skewed case as open. (This
matches the risk note in the research plan: the skewed generalization is the part of T4 most likely to
hide subtlety, and we decline to overclaim it.)

### Summary of T4

- For a balanced linear codec (K classes, each a coset of the homophone subspace C, alpha = 1/K), the
  idealized non-member mass on each class is the step function: 1/K' on each of the K' = |pi(W)| hit
  classes, 0 on the rest, where pi : GF(2)^M -> Q = GF(2)^M / C is the class-naming projection.
- FULL codec control (mass = alpha = 1/K for every class) holds IFF W is transversal to the class
  partition, i.e. pi(W) = Q, i.e. rank pi|_W = log2 K. For prefix_codec's left-aligned canonical
  patterns this is gf2_rank(stored patterns) = log2 K.
- The threshold is SHARP. Below it (rank pi|_W < log2 K) the K' hit classes are each over-weighted by
  the factor K/K' > 1 and the K - K' missed classes are exactly zero; there is no intermediate regime.
  The transition is a step in the integer rank pi|_W.
- The skewed (variable-length) codec lacks a single homophone subspace; the abstract full-control
  condition is "W meets each class in proportion to its size," and a complete characterization
  (including whether sharpness survives) is deferred as open.

## T5: the real-incidence deviation

### The gap T5 measures

T1 is an idealization (model M1): it posits that the per-key band acts uniformly
on the proven support, a_y^T z ~ Uniform(W), and derives from that the codec-
controlled law P(out = v) = |class(v) intersect W| / |W|. The real band is only
near-uniform on W, for the three reasons recorded in the T1 division-of-labor
note: (1) a_y is the DETERMINISTIC image of `membership_fingerprint(y)` through
the fixed mixing in `row_spec_for`, not a fresh uniform draw; (2) the 64-bit
`coeffs` word is pinned ODD (its low bit is forced to 1), so the band support A
is not a subspace; and (3) every set bit of a_y lies in a single 64-slot window,
so one band cannot select two rows more than 63 apart (limited reach). T5
quantifies the resulting deviation of the real non-member law from the
idealized M1 law. Writing law_real for the actual non-member output
distribution of a solved build and law_M1 for the Uniform(W)-induced law of T1,
the object of interest is

    delta := TV(law_real, law_M1).

Above the span threshold (T4, rank pi|_W = log2 K) the M1 law coincides with the
codec's codespace shares alpha, so delta is exactly the total-variation distance
between the real non-member distribution and alpha. This is the quantity the E3
benchmark reports via `measure_tv_to_codespace`, and the quantity the per-build
baseline of E2 isolates. We treat T5 as a `[characterize]` result: we attempt a
clean bound, find it resists a closed form, and deliver an empirical
characterization together with an honestly labeled big-O statement. We do NOT
prove a closed-form bound on delta.

### The empirical characterization: small and scale-independent (E3)

E3 (`benchmarks/scale/results.csv`, `results.md` in the bijou repo) fixes one
above-threshold configuration, the balanced M = 8, K = 8 codec storing all 8
values (stored canonical patterns span a rank-3 = log2 8 subspace at every N),
and sweeps the number of stored keys N across four orders of magnitude, measuring
delta as mean TV-to-codespace over R build seeds with n_q = 100000 non-member
queries per build:

    N        reps   mean TV     95% CI
    1e4      10     0.00352     [0.00313, 0.00392]
    1e5      10     0.00311     [0.00262, 0.00359]
    1e6       5     0.00352     [0.00272, 0.00432]
    1e7       3     0.00284     [0.00230, 0.00339]

Two findings. (a) The deviation is SMALL: order 0.003 in TV, two orders of
magnitude below the 0.1 scale that would signal a breakdown of codec control.
(b) The deviation is SCALE-INDEPENDENT: it is flat in N across 1e4 to 1e7, if
anything drifting weakly downward (0.0035 to 0.0028), and all four confidence
intervals overlap. The ribbon's epsilon auto-scaling, which widens the band as N
grows to keep large systems solvable, does NOT degrade codec control: the near-
uniformity of the real band on W holds at 10M keys exactly as at 10K. For T5
this means the gap between the idealized uniform-on-W law and the real band is a
small, N-stable constant for fixed support richness, not a quantity that erodes
as the stored set grows.

### The sampling-floor analysis: delta is at or below measurement resolution

The crux of an honest T5 characterization is to decide whether the measured ~0.003
is the SYSTEMATIC deviation of the true non-member law from M1, or merely the
QUERY SAMPLING-NOISE FLOOR. Each E3 build estimates the non-member law from
n_q = 100000 finite queries over K = 8 codec classes. Even if the true non-member
law were EXACTLY uniform-on-W (delta = 0), the empirical class frequencies would
fluctuate around it, producing a strictly positive observed TV-to-truth purely
from sampling.

Quantify that floor. Under M1 above threshold each class has probability
pbar = 1/K = 1/8. The observed share of class v is a Binomial(n_q, p_v)/n_q count,
and the expected TV between the empirical estimate and the true law is

    E[TV_sampling] = (1/2) sum_v E| hat p_v - p_v |.

For a binomial, de Moivre's mean-absolute-deviation identity gives
E|X - n p| = 2 (1 - p) (m + 1) C(n, m + 1) p^(m+1) (1 - p)^(n - m - 1) with
m = floor(n p); dividing by n converts to E| hat p - p |. (The normal
approximation E| hat p_v - p_v | ~ sqrt(2 / pi) sqrt(p_v (1 - p_v) / n_q) agrees to
four decimals here.) Evaluating for the E3 settings (K = 8 equal classes,
p_v = 1/8, n_q = 100000):

    E[TV_sampling floor] = 0.00334    (exact binomial MAD and normal approx agree).

A note on the right deviation measure (it is the MAD, not the standard error).
The summand E| hat p_v - p_v | is a MEAN ABSOLUTE DEVIATION, not a standard
deviation: for an unbiased estimate the expected TV-to-truth is built from the
average absolute error, and for an approximately normal hat p_v the MAD is the
factor sqrt(2 / pi) ~ 0.80 SMALLER than the standard error sqrt(p_v (1 - p_v) /
n_q). A reader who (loosely) sums the per-class STANDARD ERRORS instead, the
cruder proxy (1/2) sum_v sqrt(p_v (1 - p_v) / n_q), gets 0.00418 for these
settings, which is an upper proxy that overstates the true expected TV by exactly
that 1 / 0.80 = 1.25 factor. We use the correct MAD-based value 0.00334, which the
exact de Moivre identity and the sqrt(2 / pi) normal form both deliver.

Compare to the data. The measured E3 mean TV is 0.0028 to 0.0035 (mean ~0.0032),
and the computed floor 0.00334 lies INSIDE all four E3 confidence intervals; the
N = 1e6 point sits essentially on it and the N = 1e7 mean (0.00284) falls BELOW
it. The measured deviation therefore STRADDLES the sampling floor rather than
exceeding it. Modeling the systematic part D as adding in quadrature with the
sampling noise S (observed^2 ~ S^2 + D^2; this decomposition is HEURISTIC because
TV is an L1/mean-absolute quantity, not an L2/variance quantity, so the quadrature
is an approximate model, not an exact identity), the most over-floor point (0.0035)
implies D <= 0.0011 as a heuristic estimate, and the at-or-below-floor points imply
D indistinguishable from 0.

CONCLUSION (the strongest honest statement). At n_q = 100000 the systematic T5
deviation of the real ribbon band from Uniform(W) is at or below the
~0.0033 query-sampling-noise floor: it is BELOW measurement resolution for
support comfortably above the span threshold. The real band realizes the M1
idealization to within sampling precision for rich-enough support; the residual
~0.003 the historical anchor reports is dominated by finite-query noise, not by a
real systematic gap. (Sharpening this further is a measurement-budget question,
not a structural one: shrinking the floor requires raising n_q, since the floor
scales as n_q^(-1/2). The E2 tighter run at n_q = 100000 already nudges the rich-
support baselines down toward ~0.0025, consistent with a floor that shrinks with
query count while the underlying systematic delta stays buried beneath it.)

### The redundancy dependence: the one visible T5 effect (E2)

The genuine, VISIBLE T5 effect is governed not by N but by storage REDUNDANCY:
how far above the span threshold W sits, i.e. how many independent stored keys
back each codec class. E2 (maph benchmark `benchmarks/bench_freq_independence.cpp`,
result data in the bijou repo at `benchmarks/freq_independence/results.csv`) makes
this explicit. It fixes the skewed length-{1, 2, 2} codec
(codespace shares 0.5 / 0.25 / 0.25) on support {V0, V1, V2}, all profiles at
GF(2) rank 2 = log2 K, and reports a per-build same-profile cross-seed baseline
(building one profile twice with different seeds and TV-ing the two non-member
laws). This baseline isolates per-build T5 variance plus sampling noise:

    profile   freq (V0/V1/V2)    same-profile baseline TV
    uniform   33 / 33 / 33       0.0029
    mid       50 / 25 / 25       0.0036
    skew_b    90 /  5 /  5       0.0038
    skew_a    99 / 0.5 / 0.5     0.0190

The three rich-support profiles sit at the floor (~0.003, matching the n_q =
50000 cross-empirical floor of ~0.0034 for these unequal shares). The skew_a
profile is ELEVATED to ~0.0190 (and ~0.0168 in the tighter run, where sampling
noise is reduced but the elevation persists, confirming it is per-build T5
variance, not sampling noise). The cause is thin support: at 99 / 0.5 / 0.5 the
minority values V1, V2 are each stored only about 25 times, so although W reaches
rank 2, it does so with almost no REDUNDANCY: W sits at the threshold EDGE, and
the solved band on that barely-spanning W is meaningfully less uniform per build.

So the T5 characterization is: delta is a function of how far above the span
threshold W sits (the per-class storage redundancy), and is essentially
INDEPENDENT of N for fixed redundancy. Rich support (many keys per class, W
comfortably above threshold) gives delta at the floor (~0.003); thin support (few
keys per class, W at the threshold edge) gives a mildly elevated delta (~0.017).
N moves neither regime; redundancy moves both. The scale-independence of E3 and
the redundancy-dependence of E2 are the same statement from two directions:
growing N at fixed support richness does not change delta, but thinning a class's
support toward the threshold does.

IMPORTANT (T5 elevation does not undermine T3 / FreqDist). Even in the thin-
support elevated regime, E2 showed that the elevated deviation does NOT encode
storage frequency. The cross-PROFILE advantage tracks the per-build baseline of
the noisier profile in the pair, not the frequency gap: uniform-vs-skew_a, mid-
vs-skew_a, and skew_b-vs-skew_a all land at the same ~0.014 magnitude despite
very different frequency gaps, of the same order as (and bounded by) skew_a's own
~0.019 baseline,
while uniform-vs-skew_b (a real 33-vs-90 gap, both rich) sits at the ~0.0036
floor. The T5 elevation is a symmetric per-build noise of the thin profile, not a
frequency-difference signal. Hence T5 elevation does not break the frequency
independence of T3: it only LOOSENS the constant in the FreqDist advantage bound
(the bound is governed by the larger of the two builds' delta values), without
introducing any term that grows with the frequency gap.

### The bound statement (honestly labeled)

We do NOT prove a closed-form bound on delta = TV(law_real, law_M1). We
characterize it empirically (E3, E2) and state:

  OBSERVATION (T5, empirical). For support comfortably above the span threshold
  (each codec class backed by many independent stored keys), the deviation of the
  real ribbon band from Uniform(W) is delta = O(sampling floor) and is
  indistinguishable from zero at the measured query budget: the measured TV
  equals the n_q^(-1/2) query-sampling-noise floor (0.00334 at n_q = 100000 for
  K = 8) to within confidence intervals, scale-independently in N up to 1e7. As W
  approaches the span threshold (a codec class backed by only a handful of stored
  keys), delta grows mildly, to ~0.017 at the threshold edge (E2 skew_a, minority
  classes stored ~25 times), and is governed by the per-class store count
  (redundancy), not by N or by the storage frequencies.

  CONJECTURE (qualitative, NOT proven). The visible part of delta is controlled by
  the redundancy of the stored system beyond the threshold dimension, equivalently
  by the minimum per-class store count m_min: delta is at the sampling floor once
  m_min is large and degrades only as m_min falls toward the minimum needed to
  span. We offer this as the pattern the data exhibit (E2's monotone baseline in
  decreasing minority-store count; E3's flatness at fixed large redundancy), not
  as a theorem. A structural proof, presumably bounding the non-uniformity of a
  banded GF(2) solution on a subspace W in terms of the number of independent
  equations pinning W, is left open.

This is deliberately weaker than the T1 through T4 results, which ARE proven. T5
is the place where the real construction meets the idealization, and the honest
deliverable is the measurement plus the big-O, not a bound we did not derive.

### The security hook (brief; formalized in the security section below)

The FreqDist advantage between two storage profiles p0 and p1 with the SAME
support satisfies Adv <= 2 TV(law_real under p0, law_real under p1). Both real
laws are within delta of the SAME idealized M1 law (which is frequency-
independent by T3, since W depends only on the support). By the triangle
inequality, TV(law_real(p0), law_real(p1)) <= delta(p0) + delta(p1), so

    Adv <= 2 (delta(p0) + delta(p1)),

a residual bounded by ~4 times the per-build T5 deviation: ~0.012 for rich
support on both sides (delta ~ 0.003 each, so Adv <= 2(0.003+0.003) = 0.012) and
up to ~0.04 when one profile is at the threshold edge (delta ~ 0.017 for the thin
side and ~0.003 for the rich side, so Adv <= 2(0.017+0.003) = 0.04). Crucially,
per E2 this residual does NOT grow
with the frequency gap between p0 and p1: it is governed by the redundancy of the
thinner profile, not by how different the two frequency vectors are. T5 thus caps
the frequency-analysis leakage of the non-member channel at a small constant set
by storage redundancy, independent of the plaintext frequencies. The formal
FreqDist security statement, with the game definition and the exact constant, is
the security section below ("Security: frequency-analysis resistance (the FreqDist
game)"); T5 supplies the deviation budget it consumes.

### Summary of T5

- T5 characterizes delta = TV(law_real, law_M1), the deviation of the real near-
  uniform ribbon band from the T1 idealization Uniform(W). It is a
  `[characterize]` result: empirical characterization plus a labeled big-O, NOT a
  proven closed-form bound.
- E3: delta is SMALL (~0.003 in TV) and SCALE-INDEPENDENT (flat in N from 1e4 to
  1e7, overlapping CIs; epsilon auto-scaling at 10M does not degrade control).
- Sampling-floor analysis: the n_q = 100000 query-sampling-noise floor is 0.00334
  (exact binomial MAD = normal approx), and the measured TV straddles it (inside
  every CI, below it at 1e7). The SYSTEMATIC T5 deviation for rich support is
  therefore at or below measurement resolution: the real band realizes M1 to
  within sampling precision.
- E2: the one visible T5 effect is REDUNDANCY-governed. Rich support gives delta
  at the floor (~0.003); thin support at the threshold edge (skew_a, minority
  classes stored ~25 times) gives delta ~0.017. N does not move delta; per-class
  store count does. The elevation does NOT encode storage frequency (cross-
  profile advantage tracks the per-build floor, not the frequency gap), so it does
  not break T3, it only loosens the FreqDist constant.
- Security hook: Adv <= 2 (delta(p0) + delta(p1)) bounds the residual FreqDist
  advantage by ~0.012 (both sides rich) to ~0.04 (one side at threshold edge),
  frequency-gap-independent; this is formalized in the security section below.

## Security: frequency-analysis resistance (the FreqDist game)

This section is the formal home of the frequency-analysis security claim. T3
established the lemma the claim rests on (the non-member law depends on the value
support and the codec only, never the storage multiplicities) and T5 established
the deviation budget the real construction spends against the idealization. The
brief "Consequence for security (FreqDist)" note under T3 and the "security hook"
note under T5 are consequences of what follows; this section states the game
precisely, proves the idealized advantage is exactly zero, bounds the real
advantage by the T5 budget, and is careful about what it does and does not cover.

### Threat model

The adversary has ORACLE access to a single deployed instance: it may query the
structure on chosen keys and observe the returned values, adaptively. The
restriction that makes this a clean statement is that the adversary queries only
NON-MEMBER keys. (Member keys return their stored canonical value by
construction and are not the object of study here; the interesting channel is
what the structure says about keys it was not built on.) The adversary's goal is
to learn the storage-frequency distribution of values among the member set S:
how often each plaintext value is actually stored, the multiplicities m_v of T3.

This is the classical frequency-analysis surface. A deterministic substitution
cipher, or deterministic / property-preserving encryption used as an encrypted-
search index, leaks plaintext frequency directly: equal ciphertexts mean equal
plaintexts, so the histogram of ciphertexts is the histogram of plaintexts up to
relabeling, and an adversary with auxiliary frequency knowledge recovers the map.
This is the attack of Naveed, Kamara, and Wright on property-preserving encrypted
databases, and the leakage that PANCAKE (Grubbs et al.) neutralizes by frequency-
smoothing the access distribution. The point of this section is that the non-
member channel of codec-controlled retrieval leaks frequency STRUCTURALLY not at
all: not because frequencies are smoothed or padded, but because they never enter
the law the channel samples from (T3). The references here are prose context, not
a formal bibliography; the bibliography is the paper's concern.

### The game (FreqDist)

Fix a value support supp and a codec, both PUBLIC. The distinguishing game between
a challenger and an adversary A runs as follows.

1. A chooses two storage-frequency distributions p0 and p1 over the SAME support
   supp, with arbitrary, possibly very different, multiplicities. (For example
   p0 may pile almost all mass on one value and p1 may be balanced; only the set
   of distinct values is required to agree, which is what fixes a common W by T3.)

2. The challenger samples b <- {0, 1} uniformly, builds the structure
   `encoded_retrieval<ribbon_retrieval<M>, codec>` from a key set whose value
   assignment realizes the frequency profile p_b, and gives A oracle query access
   to the built instance.

3. A issues queries on NON-MEMBER keys of its choice, observes the returned
   (decoded) values, and finally outputs a guess b' in {0, 1}.

The advantage is

    Adv(A) = | 2 * Pr[b' = b] - 1 |,

the standard distinguishing advantage (0 for a guess no better than a coin, 1 for
perfect distinguishing). A wins to the extent it can tell which frequency profile
was deployed from non-member outputs alone, which is exactly recovering storage
frequency information.

The game is meaningful only ABOVE the span threshold (T4): below threshold the
codec does not control the output law at all (the step-function regime of T4
applies and the support is too thin to realize the codespace shares), so the
comparison is not about frequency in the intended sense. We therefore assume supp
is above threshold (rank pi|_W = log2 K, the natural deployment regime in which
both p0 and p1 induce full codec control). Both profiles share this W because they
share supp (T3).

### Idealized result: zero advantage under M1

THEOREM (FreqDist, idealized, model M1). Under the idealization M1 the FreqDist
advantage is exactly zero: Adv(A) = 0 for every adversary A, computationally
unbounded and adaptive included.

PROOF. By T3, the stored-pattern span W is a function of supp alone and is
invariant under any change of the multiplicities that preserves the support; p0
and p1 share supp, hence induce the same W. By T1 (Step 5) the idealized non-
member output law under either profile is

    P(out(y) = v) = |class(v) intersect W| / |W|,

a function of W and the codec's decode classes only, with no multiplicity term.
Both inputs (W, and the classes class(v)) are identical for p0 and p1. Therefore
the non-member output law under p0 EQUALS the non-member output law under p1: the
two oracles A interacts with are the SAME distribution. No function of identically
distributed observations can distinguish their source, so Pr[b' = b] = 1/2 for
every A regardless of the number or adaptivity of queries, and Adv(A) = 0. QED.

The content is entirely T3 (W depends only on supp; multiplicities do not enter)
plus T1 (the law is a function of W and the codec). The advantage is zero not
because distinguishing is hard but because there is nothing to distinguish: the
two oracles are one and the same law.

### Real bound: advantage at most twice the summed T5 deviation

Under the real construction the two oracles are not exactly equal: each profile's
build solves its own banded GF(2) system and so has its own solution matrix z,
inducing its own near-uniform (rather than exactly uniform) law on the shared W.
Write law_real(p_b) for the real non-member output law under profile p_b and recall
delta(p_b) = TV(law_real(p_b), law_M1), the per-build T5 deviation from the shared
M1 law. (The M1 law is the SAME object for both, being frequency-independent by
T3: W is common, so law_M1 is common.)

The standard fact that statistical distinguishing advantage is bounded by total
variation gives

    Adv(A) <= 2 * TV(law_real(p0), law_real(p1))

for any adversary observing samples from one of the two laws. (The factor 2 is the
convention attached to Adv = |2 Pr[b' = b] - 1|; with the alternative convention
Adv = |Pr[b' = b in 0,1] - 1/2| the bound reads <= TV. The optimal single-sample
distinguisher achieves exactly the TV; the bound is the per-instance leakage cap.)
The clean way to bound the right-hand side is per realization against the shared
idealization: each profile's realized non-member law is within its own T5 deviation
of the SAME M1 law (the M1 law is common because W is common, by T3), so by the
triangle inequality for TV the two realized laws are within the sum of their
deviations of each other. Concretely, routing through the common M1 law,

    TV(law_real(p0), law_real(p1))
        <= TV(law_real(p0), law_M1) + TV(law_M1, law_real(p1))
        =  delta(p0) + delta(p1),

so

    Adv(A) <= 2 ( delta(p0) + delta(p1) ).

This is the real FreqDist bound. It is the T5 security hook, now derived in the
game. Plugging in the T5 numbers (the deviation budget T5 supplies):

  - Both profiles rich (each codec class backed by many keys, W comfortably above
    threshold): delta(p0) ~ delta(p1) ~ 0.003, so Adv(A) <= 2(0.003 + 0.003) =
    0.012.
  - One profile at the threshold EDGE (a minority class stored only a handful of
    times, the E2 skew_a regime): delta ~ 0.017 on the thin side and ~0.003 on the
    rich side, so Adv(A) <= 2(0.017 + 0.003) = 0.04.

E2 (the empirical FreqDist experiment, generated by maph's
`benchmarks/bench_freq_independence.cpp` with result data in the bijou repo at
`benchmarks/freq_independence/results.csv`) CONFIRMS this bound and, more
tellingly, confirms its SHAPE. The measured cross-profile
advantage sits at the per-build noise floor and does NOT grow with the frequency
gap between p0 and p1. The cross-profile pairs uniform-vs-skew_a, mid-vs-skew_a,
and skew_b-vs-skew_a all land at the same ~0.014 magnitude, tracking the noisier
(thin) profile skew_a's own same-seed ~0.019 baseline, despite the three pairs
having very different storage-frequency gaps (33/33/33, 50/25/25, and 90/5/5 each
against 99/0.5/0.5). The pair uniform-vs-skew_b (a real 33-vs-90 frequency gap,
both profiles rich) sits at the ~0.0036 floor. So the advantage is governed by the
redundancy of the thinner build (its delta), exactly as 2(delta(p0) + delta(p1))
predicts, and is independent of the frequency difference, exactly as the idealized
Adv = 0 demands. The measured advantage is the residual T5 noise, not a frequency
signal.

### Why this is an independence result, not a comparative one

The claim is an INDEPENDENCE statement: the non-member channel is independent of
storage frequency. The idealized form is the cleanest possible such statement,
the two oracles are the identical distribution, Adv = 0; the real form weakens it
only to a small constant set by per-build deviation, with no frequency-gap term.
It is NOT a comparative claim of the form "codec X leaks c times less frequency
than codec Y," and it is deliberately not phrased that way. A comparative,
directional reading is exactly what admitted the sign error in the multi-instance
coincidence-oracle analysis, where "minimizes the coincidence sum" was misread as
"defends better" when the defender direction is the reverse (see the reconciliation
subsection below, and its CORRECTION note). An indistinguishability statement
carries no direction to invert: Adv = 0 means the channel reveals nothing about
frequency, full stop, and the real bound caps the residual symmetrically in
delta(p0) and delta(p1) with no sign attached to which profile is "more
concentrated." What the non-member channel does carry is only the PUBLIC codec
shares q = (alpha(v)) (above threshold the law equals alpha; the q here is the
codespace-share vector of T4), and the support, both public design choices. It
never carries the private storage frequencies m_v.

### Scope and boundary

This section defends exactly one channel against exactly one attack, and it is
worth being explicit about the perimeter.

  - What it covers. The value-FREQUENCY channel of non-member outputs: an adversary
    with non-member oracle access cannot learn the storage-frequency distribution
    of values in S. Idealized advantage zero (M1, from T1 and T3); real advantage
    at most 2(delta(p0) + delta(p1)), a small constant governed by storage
    redundancy and independent of the frequency gap (T5, E2).

  - What it does NOT cover. It says nothing about access-pattern leakage (which
    keys are queried, and any correlation structure across queries), nothing about
    volume / size leakage, and nothing about the multi-instance coincidence oracle.
    The coincidence oracle is a DIFFERENT game (the adversary correlates t shared-
    function redeployments and predicts membership from output coincidence, not
    frequency from a single instance); it is defeated by CONCENTRATION of alpha,
    the opposite codec choice from the one that is harmless here, and it is treated
    in the reconciliation subsection below. The two games have opposite optimal
    codecs, which is the central tension that subsection resolves.

  - Standing assumption. Above-threshold support (T4, rank pi|_W = log2 K) is
    assumed throughout, so that both profiles realize full codec control and the
    common-W argument of T3 applies. Below threshold the game is not the intended
    frequency game.

We do not claim a general confidentiality result. The honest statement is
narrow and strong: on its one channel, against its one attack, in its deployment
regime, frequency analysis has no purchase, structurally, by T3, with a quantified
real-world residual from T5.

## The two attacks pull opposite ways: reconciliation

The security story so far has one attack in it: single-instance frequency
analysis, defeated by T3 (frequency independence). There is a second, structurally
different attack on the SAME construction, the multi-instance coincidence oracle,
and the codec choice that defeats one attack is the WORST choice against the
other. This section states both, fixes a sign error that has circulated in the
companion writeups, and frames the resulting tension as a clean finding rather
than a defect: there is no single most-confidential codec; the optimal codec is
attack-model-dependent.

### Attack 1 (single instance): frequency analysis, defeated by independence

The adversary sees ONE deployed instance and wants to recover the storage
frequency distribution (the m_v, equivalently how often each plaintext value is
actually stored), as in classical frequency analysis against a substitution
cipher. T3 is the answer. The non-member output law is
P(out = v) = |class(v) intersect W| / |W|, a function of the value support
(through W) and the codec only; the storage multiplicities m_v never enter it.
Two databases with identical support but opposite frequency profiles present
statistically indistinguishable non-member output distributions (the contrastive
`[contrastive]` test confirms this: 99/0.5/0.5 vs 50/25/25 storage, output gaps
~0.004). So ANY above-threshold codec (T4: rank pi|_W = log2 K) defeats
single-instance frequency analysis outright; the storage frequencies are simply
not in the channel.

What residual the non-member channel DOES leak is the public codec shares alpha
(above threshold, the law equals alpha exactly; below it, the step-function
profile of T4), plus the support, both of which are public design choices, not
secrets. If one is worried about even this residual leaking something about value
IMPORTANCE (a Huffman codec's short codeword for value v announces "v is
frequent, that is why it got a short code"), the way to minimize what alpha
reveals is to FLATTEN it: a uniform alpha = 1/K carries no per-value ordering
information at all. So within attack 1, the pressure on the codec is toward FLAT /
uniform shares (minimal mutual information between alpha and the value
importance ranking).

### Attack 2 (multi-instance): the coincidence oracle, defeated by concentration

The adversary sees t instances that share the same (S, f) and differ only in
per-instance non-member randomness (a shared-function redeployment). The
coincidence oracle predicts "k in S" iff all t observed outputs are equal. For a
member, all t canonical encodings equal f(k), so the coincidence event C always
holds; for a non-member, the t outputs are i.i.d. draws from alpha and coincide
with probability sum_v alpha(v)^t. At a balanced prior the attacker accuracy is

    acc(t) = 1 - (1/2) * sum_v alpha(v)^t.

Write S(t) = sum_v alpha(v)^t (the coincidence sum). The defender wants acc(t)
SMALL, hence S(t) LARGE. For fixed sum_v alpha(v) = 1 and t >= 2, S(t) is
MAXIMIZED by a CONCENTRATED (Huffman-like) distribution (S(t) -> 1 as the mass
piles onto a few values) and MINIMIZED by the UNIFORM distribution (S(t) =
K^(1 - t), small). Therefore:

- CONCENTRATED / Huffman alpha gives acc(t) near 1/2: the BEST defense.
- UNIFORM alpha gives acc(t) near 1: the WORST defense.

Within attack 2, the pressure on the codec is toward CONCENTRATED shares, the
exact opposite of attack 1.

The corrected E4 result confirms this direction independently. The Monte Carlo
in `analysis/coincidence_oracle.py` (K = 8, t = 1..8) matches the closed form
for every (codec, t) cell inside a 95% CI, and shows attacker accuracy monotone
DECREASING in concentration at every t >= 2: uniform is the unique WORST defense,
and every concentrated codec strictly beats it. At t = 4 the numbers are uniform
acc ~0.999 (worst) versus huffman acc ~0.967 (better), and ~0.672 for a
codec that puts 0.90 of the codespace on one value (more concentration, still
better defense).

CORRECTION (a sign error in the companion writeups). An earlier reading claimed
the UNIFORM codec is the BETTER multi-instance defense, on the grounds that it
MINIMIZES S(t) = sum_v alpha(v)^t and that minimizing the coincidence sum looks
protective. That reverses the defender direction: acc(t) = 1 - S(t)/2, so a
SMALLER S(t) means a HIGHER attacker accuracy, i.e. a WORSE defense, not a better
one. The "uniform defends best (16x better)" claim is the direction-reversed
reading and is wrong; the correct statement is concentrated / Huffman defends
best. This inversion was corrected in the bernoulli source experiment
`src/bernoulli/experiments/RESULTS_14.md` (and the matching docstring of
`14_coincidence_oracle.py`) in commit `1a8bebe` on 2026-05-17 (R7 CRIT-1);
the current file there is correct, but the inverted statement survives in that
file's git history (the parent of `1a8bebe`), and the cipher-maps section 10.6
paragraph carries the same inversion. FOLLOW-UP: the cipher-maps section 10.6
(and any other location that still says uniform defends best at large t) should
be corrected to the concentrated-wins direction. We do NOT edit the bernoulli or
cipher-maps repositories as part of this note; this is flagged as the action item.

### The synthesis: opposite pulls, so the optimal codec is attack-model-dependent

The two attacks pull the codec in OPPOSITE directions:

- Attack 1 (frequency analysis, single instance) is best served by FLAT / uniform
  alpha: it already loses to independence (T3), and flat shares minimize what the
  public channel reveals about value importance.
- Attack 2 (coincidence oracle, multi-instance) is best served by CONCENTRATED /
  Huffman alpha: it minimizes acc(t) = 1 - S(t)/2 by maximizing the non-member
  coincidence sum S(t).

THE FINDING. There is no single most-confidential codec. The flat corner is
optimal against the single-instance leakage channel; the Huffman corner is
optimal against the multi-instance coincidence oracle (and, separately, against
storage SPACE, since a Huffman codec minimizes expected codeword length). Which
corner you want depends on the threat model: how many shared-function instances
will the same adversary ever correlate? At t = 1 (no redeployment) the
single-instance pressure dominates and flat is preferable; at large t (heavy
shared-function redeployment) the coincidence oracle dominates and Huffman is
preferable.

This is exactly the linear-retrieval instance of the cipher-maps (TV, length)
Pareto frontier. There the two competing objectives are leakage (total-variation
distance of the output law from a frequency-revealing target, minimized by the
flat / TV-optimal corner) and cost (expected codeword length, minimized by the
Huffman / space-optimal corner). Codec-controlled retrieval realizes the same
frontier with a security reading on the cost axis: the Huffman corner is not only
space-optimal but coincidence-optimal, and the flat corner is not only
TV-optimal but importance-leakage-optimal. The opposite-pull is therefore not a
flaw in the construction but the expected shape of a Pareto problem: the corners
optimize different objectives, and a deployment picks its operating point on the
frontier according to which attack it most needs to resist. Framing it as a clean
finding: codec-controlled retrieval exposes a single, public, tunable lever
(alpha) that trades single-instance importance-leakage against multi-instance
coincidence-resistance (and space), with the two security objectives sitting at
opposite ends of the same frontier.

## Experiments

This section consolidates the four experiments the theorems above reference into
one place with the actual measured numbers. Each experiment is generated by an
artifact in the maph repository (a benchmark binary or analysis script) and its
result data is committed in the companion bijou repository; both paths are cited
per experiment. The numbers in the tables below are read directly from those
result files. Nothing here introduces a new claim: E1 is the empirical face of
the T4 threshold, E2 of the T3/FreqDist independence and the T5 redundancy
effect, E3 of the T5 scale-independence and sampling-floor analysis, and E4 of
the reconciliation (coincidence-oracle) direction.

### E1: the span threshold is sharp (T4)

Generating artifact: maph `benchmarks/bench_codec_span.cpp`. Result data: bijou
`benchmarks/codec_span/results.csv`. The benchmark fixes a balanced codec, sweeps
the number of distinct stored values (hence the GF(2) rank of the stored
canonical patterns), and reports the mean TV of the non-member output law to the
codec's codespace shares alpha, averaged over build seeds. T4 predicts a step:
above the threshold rank pi|_W = log2 K the law equals alpha (TV near 0); one
rank below it the law cannot reach alpha and TV is large. The table shows the two
flanking ranks for each balanced config.

    config           rank just below log2 K        rank == log2 K
                     (rank, mean_tv)               (rank, mean_tv)
    balanced_M4_K4   rank 1, 0.500                 rank 2, 0.00277
    balanced_M8_K8   rank 2, 0.500                 rank 3, 0.00505

The transition is a cliff, not a ramp: TV drops from 0.5 to ~0.003 (the T5 floor)
as the rank crosses log2 K, with no intermediate value, exactly the step function
of T4. Below the threshold the per-config TV is deterministic in the rank, not a
sampling average (the step-function masses of T4 are fixed dyadic rationals on the
enumerated W), so the reported sub-threshold confidence intervals are DEGENERATE:
ci_lo = mean = ci_hi at every below-threshold row (for example balanced_M8_K8 at
rank 0, 1, 2 reads 0.875, 0.750, 0.500 with zero-width intervals). Only at and
above the threshold, where the residual is the T5 near-uniformity gap measured
over finite queries, do the intervals acquire width (balanced_M4_K4 rank 2:
[0.00215, 0.00340]; balanced_M8_K8 rank 3: [0.00455, 0.00556]). A skewed config in
the same file (skewed_M4) shows the analogous drop to 0.00238 at rank 2, with a
non-degenerate sub-threshold value at rank 1 (0.251) because the skewed class
sizes make the below-threshold mass a non-trivial average rather than a single
dyadic constant.

length-{1, 2, 2} codec (codespace shares 0.5 / 0.25 / 0.25) on support
{V0, V1, V2}, all profiles above the span threshold (GF(2) rank 2 = log2 K), and
reports two quantities: a same-profile cross-seed BASELINE (build one profile
twice under different seeds, TV the two non-member laws; this isolates per-build
T5 variance plus sampling noise) and the CROSS-profile advantage (TV between the
non-member laws of two different storage profiles). T3 predicts the cross-profile
advantage does not track the frequency gap; T5 predicts the one profile at the
threshold edge (skew_a) carries an elevated per-build deviation.

    profile / pair                same-profile baseline       cross-profile advantage
    uniform (33/33/33)            0.00292                     ---
    mid     (50/25/25)            0.00360                     ---
    skew_b  (90/ 5/ 5)            0.00381                     ---
    skew_a  (99/0.5/0.5)          0.01897                     ---
    uniform vs mid                ---                         0.00324
    uniform vs skew_b             ---                         0.00364
    mid     vs skew_b             ---                         0.00402
    uniform vs skew_a             ---                         0.01336
    mid     vs skew_a             ---                         0.01433
    skew_b  vs skew_a             ---                         0.01458

Reading. The three rich profiles (uniform, mid, skew_b) sit at the ~0.003 floor in
both columns. The cross-profile advantage tracks the NOISIER profile of the pair,
not the frequency gap: the three pairs that include the thin skew_a profile
(uniform-vs-skew_a, mid-vs-skew_a, skew_b-vs-skew_a) all land at the same ~0.014
magnitude, of the same order as and bounded by skew_a's own ~0.019 same-profile
baseline, despite their storage-frequency gaps differing enormously (33/33/33,

between two RICH profiles, uniform-vs-skew_b (33-vs-90, both well above
threshold), sits at the ~0.0036 floor. So the elevation is a per-build property of
THIN support (skew_a stores its minority values only ~25 times each, leaving W at
the threshold edge with almost no redundancy), a T5 effect, not a frequency-leakage
signal. This is the empirical confirmation of both the T3 independence (advantage
does not grow with the frequency gap) and the T5 redundancy characterization
(advantage is set by the per-class store count of the thinner build), and it
realizes the FreqDist real bound Adv <= 2(delta(p0) + delta(p1)) with the residual
governed by the thinner profile's delta.

### E3: the deviation is small and scale-independent (T5)

Generating artifact: maph `benchmarks/bench_codec_span.cpp` (the scale-sweep mode).
Result data: bijou `benchmarks/scale/results.csv`. The benchmark fixes one
above-threshold configuration (balanced M = 8, K = 8, all 8 values stored, rank 3
= log2 8 at every N) and sweeps the stored-key count N across four orders of
magnitude, reporting mean TV-to-codespace over build seeds with 100000 non-member
queries per build.

    N        reps    mean_tv     95% CI
    1e4      10      0.00352     [0.00313, 0.00392]
    1e5      10      0.00311     [0.00262, 0.00359]
    1e6       5      0.00352     [0.00272, 0.00432]
    1e7       3      0.00284     [0.00230, 0.00339]

The deviation is order 0.003 in TV (two orders of magnitude below a 0.1 breakdown
scale) and is FLAT in N from 1e4 to 1e7 (if anything drifting weakly downward),
with all four confidence intervals overlapping; the ribbon's epsilon auto-scaling
at 10M keys does not degrade codec control. The analytic query-sampling-noise
floor for these settings (K = 8 equal classes, p_v = 1/8, n_q = 100000) is 0.00334
(exact binomial mean-absolute-deviation, matching the normal approximation). The
measured values STRADDLE this floor: it lies inside all four confidence intervals,
the N = 1e6 mean sits essentially on it, and the N = 1e7 mean (0.00284) falls
below it. The systematic T5 deviation is therefore at or below measurement
resolution at this query budget, consistent with the T5 conclusion that the real
band realizes the M1 idealization to within sampling precision for rich support.

### E4: the coincidence-oracle direction (reconciliation)

Generating artifact: maph `analysis/coincidence_oracle.py`. Result data: bijou
`benchmarks/coincidence_oracle/results.md`. The script computes, for K = 8 values
and t = 1..8 shared-function redeployments, the coincidence-oracle attacker
accuracy acc(t) = 1 - (1/2) sum_v alpha(v)^t in closed form and confirms it by
Monte Carlo (100000 member + 100000 non-member trials per rep, 10 reps), across
codecs of increasing concentration. HIGHER acc means WORSE defense. The corrected
direction is that concentration HELPS: the most-concentrated codec is the best
defense and the uniform codec the worst, the reverse of the inverted reading that
circulated in the companion writeups. The slice at t = 4:

    codec (max share)              acc_closed     acc_mc      MC matches closed form?
    uniform (0.125)                0.99902        0.99903     yes (in 95% CI)
    intermediate_zipf (~0.34)      0.98240        0.98255     yes
    huffman (0.50)                 0.96667        0.96671     yes
    intermediate_padded (0.90)     0.67195        0.67185     yes

Reading. Attacker accuracy falls monotonically as the codec concentrates: uniform
(every value share 0.125) is the unique worst defense at acc ~0.999; the dyadic
Huffman codec (top share 0.50) improves it to ~0.967; the most-concentrated codec
(intermediate_padded, one value holding 0.90 of the codespace) is the best defense
at ~0.672. The Monte Carlo matches the closed form for every (codec, t) cell
inside a 95% confidence interval, validating acc(t) = 1 - S(t)/2. This is the
direction the reconciliation section states: smaller coincidence sum S(t) means
HIGHER attacker accuracy, so the uniform codec (which minimizes S(t)) is the worst,
not the best, multi-instance defense. E4 is thus the quantitative backing for the
opposite-pull finding: the codec that is harmless against single-instance
frequency analysis (uniform, by T3 the advantage is zero regardless) is the worst
against the multi-instance coincidence oracle, and the concentrated codec reverses
both rankings.

## Related work and novelty

This section positions the note honestly against prior art, including the author's
own prior work, so that the genuinely new content is not confused with results
that already exist elsewhere. The shared bibliography for these references is
bijou `bib/bijou.bib`. We organize the positioning as a three-tier ledger:
what is NOT novel here (it is reused baseline), what IS novel, and what is the
HEADLINE novelty.

### Tier A: not novel here (reused baseline)

The abstract law that a codec's codespace allocation controls the non-member
output distribution, P(out = v) proportional to |class(v)| / 2^M, is NOT a
contribution of this note. It already appears in two places and we cite it as
established baseline rather than headline it.

First, the author's own bernoulli_maps singular-hash-map work
(`towell_bernoulli_maps`) derives exactly this codec-output formula. There the
construction is a RANDOM-ORACLE one: the non-member output is a fresh hash of the
query, so its distribution over the codec classes is immediate from the codec's
codespace shares. The formula in the present note is the same formula; what
differs is the construction it is proven for (see Tier B).

Second, the idea that an encoder can be designed so that its output distribution
is the target distribution, regardless of the message frequencies, is the
distribution-transforming-encoder (DTE) idea of Honey Encryption
(`juels2014honey`, refined by `cheng2019pmte`). Honey Encryption builds a DTE so
that decrypting a ciphertext under a wrong key yields a plausible message sampled
from the message-space distribution; the codec here plays an analogous role for
non-member outputs. We cite Honey Encryption as the conceptual origin of
"engineer the encoder so the off-target output follows a chosen law," and do not
claim that idea as new.

### Tier B: novel (the law survives the move to a linear retrieval structure)

The novel content of T1 through T3 is that the SAME codec-output law survives the
move from a random-oracle construction to a GF(2)-LINEAR retrieval structure. In
ribbon / XOR retrieval the non-member output is not a fresh hash of the query: it
is a^T z, an XOR of selected rows of the solved solution matrix (a deterministic
linear function of the fixed stored data, as established in the T1/T2 setup). A
priori there is no reason the off-target output of such a structure should follow
the codec's codespace shares at all; the output is constrained to the
stored-pattern span W, a subspace fixed by what was stored, and the per-key
coefficient vector is a structured band, not a uniform draw. T2 proves the support
is exactly W, T1 (under the M1 idealization) and T4 (the threshold) characterize
when the law on W equals the codec shares, and T3 proves the law depends only on
the support, never the multiplicities. The retrieval / static-function literature
that ribbon retrieval descends from, Bloomier filters (`chazelle2004bloomier`),
ribbon and BuRR (`dillinger2021ribbon`, `dillinger2022burr`), and binary-fuse
filters (`graf2022binaryfuse`, after the xor filter `graf2020xor`), treats the
output on non-member keys as arbitrary, uncharacterized junk: it is the price of a
construction that only needs to be correct on the member set, and its distribution
is never studied. Characterizing that distribution, and showing it is the codec's
own codespace law (gated by the span threshold), for a GF(2)-linear retrieval
structure is the new content here.

### Tier C: headline novelty (the sharp GF(2)-span threshold, T4)

The headline result is the SHARP span threshold of T4: the non-member law equals
the codec's codespace shares exactly when the stored canonical patterns span the
full codeword space (rank pi|_W = log2 K), and the transition is a step in the
integer rank, with no intermediate regime, stated as transversality of W to the
codec's class partition. This threshold appears nowhere we are aware of, internal
or external: it is absent from the random-oracle treatments (Tier A, where there
is no span to be transversal to, the output is always a fresh hash), and absent
from the retrieval literature (Tier B, which does not study the non-member law at
all). The subspace-meets-coset lemma and the resulting K' = |pi(W)| step function
are the technical core, and the empirical cliff in E1 is its measured face.

### Differentiation from adjacent work (explicit)

Four adjacencies deserve an explicit boundary, since each shares a goal or a
formula with this note while differing in substance.

1. The author's singular-hash-map (bernoulli_maps, `towell_bernoulli_maps`). It
   contains the IDENTICAL codec-output formula, but for a random-oracle
   construction. The transfer of that formula to a LINEAR retrieval structure, and
   the discovery that the transfer is gated by a provable span threshold (T4), is
   the new content. The formula is shared; the construction and its threshold
   theorem are not.

2. The author's cipher-maps paper (`towell2026ciphermaps`). It shares the
   frequency-hiding GOAL, but its backends are random-oracle and RecSplit
   constructions with NO linear-retrieval backend, and its frequency-hiding concern
   is the QUERY-marginal distribution (which keys are asked), not the non-member
   OUTPUT channel of a linear structure. This note supplies the linear-retrieval
   backend cipher-maps lacks and proves the structural property (T3/T4) for it.
   This note is the construction-and-experiments substance destined to become the
   towell2026codec companion to cipher-maps.

3. Honey-Encryption DTE (`juels2014honey`, `cheng2019pmte`). Honey Encryption
   ASSUMES a uniform seed delivered by a cipher and builds the DTE on top of that
   assumption. Here we do not assume uniformity: we PROVE near-uniformity of the
   pre-decoding output on the stored-pattern span from the linear structure itself
   (T1 as idealization, T5 as the measured gap), gated by the span threshold (T4).
   The uniformity is a derived structural property, not an assumed primitive.

4. Frequency-smoothing encrypted databases and the attack that motivates them:
   PANCAKE (`grubbs2020pancake`), frequency-smoothing encryption FSE
   (`lacharite2018fse`), and the inference attack of Naveed, Kamara, and Wright
   (`naveed2015inference`) that exposes the leakage these defend against. They
   share the frequency-hiding GOAL, but operate at a different layer: they are
   ONLINE / encoding mechanisms (they smooth the access or encoding distribution at
   query or insert time, adding fake accesses or padding). The property here is
   STATIC and STRUCTURAL: the non-member output law of a built linear structure is
   frequency-independent by construction (T3), with no online smoothing, no fake
   traffic, and no padding. Same goal, different mechanism and different layer.

## Scope and relationship to cipher-maps

A closing note on perimeter, complementing the per-section scope statements above.
This note is self-contained: the full story (what is PROVEN, what is MEASURED, what
is NOVEL, and what is OUT OF SCOPE) is recoverable from this one file.

- PROVEN: T2 (the non-member output support is exactly the stored-pattern span W),
  T1 under the explicit M1 idealization (uniform-on-W gives the codec-controlled
  law), T3 (the law depends only on the value support and the codec, never the
  storage multiplicities), T4 (the sharp transversality threshold, full control iff
  rank pi|_W = log2 K, with a step transition), and the idealized FreqDist theorem
  (advantage exactly zero under M1). These carry proofs verified by the
  computational checks tagged [gf2], [span], [threshold], and [contrastive].

- MEASURED: T5 (the real ribbon band deviates from the M1 idealization by
  delta = TV(law_real, law_M1), characterized empirically as small and
  scale-independent, at or below the query-sampling floor for rich support, and
  governed by storage redundancy at the threshold edge), and the real FreqDist
  bound Adv <= 2(delta(p0) + delta(p1)). T5 is a [characterize] result: an
  empirical characterization plus a labeled big-O, not a proven closed-form bound.

- OUT OF SCOPE (declared open): a full characterization of the SKEWED
  (variable-length) codec threshold (T4 proves only the balanced case; whether the
  skewed transition is sharp or genuinely graded is left open), and a structural
  closed-form bound on the T5 deviation delta (the redundancy conjecture is offered
  as the pattern the data exhibit, not a theorem). The security treatment defends
  exactly one channel (the non-member value-frequency channel) against exactly one
  attack (single-instance frequency analysis), plus the reconciliation of the
  opposite-pulling multi-instance coincidence oracle; access-pattern, volume, and
  size leakage are explicitly not addressed.

Relationship to cipher-maps. The opposite-pull finding (the flat codec is optimal
against single-instance importance leakage; the concentrated / Huffman codec is
optimal against the multi-instance coincidence oracle and against storage space)
is the linear-retrieval instance of the cipher-maps (TV, length) Pareto frontier.
This note is the construction-and-experiments companion to cipher-maps: it supplies
the GF(2)-linear-retrieval backend that paper lacks, proves the span-threshold
structural property for it, and is the material destined to become towell2026codec.
